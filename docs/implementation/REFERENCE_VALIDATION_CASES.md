# Reference Validation Cases

Date: 28 November 2026. Version 1.0.0.
Every case here is a numerical comparison, not a non null
assert: the Dart engine must land within the stated
tolerance of the reference number, or the test fails.

Reference source: Skyfield 1.55 with NASA JPL DE421,
apparent geocentric ecliptic longitudes, GMST ascendant,
skyfield.almanac rise and set. Generated by
docs/implementation/generate_reference_cases.py, stored in
docs/implementation/reference_cases.json. The canonical
case was first validated against JPL Horizons DE441 in
release 9; DE421 and DE441 agree to about 0.02 degrees on
these dates, and the canonical Skyfield numbers reproduce
the DE441 numbers in test/astro_test.dart to that band.

Config for every case unless stated otherwise: ephemeris
schlyter, ayanamsa Lahiri, zodiac sidereal for the chart
and tropical for the comparison, whole sign houses, mean
node, calculation version 1.0.0. Sidereal reference values
are tropical minus the Lahiri ayanamsa on the date: 23.82
degrees on 14 March 1998, 23.85 on 29 February 2000,
24.21 on 1 December 2025, 24.23 on 8 December 2026. The
tests compute the ayanamsa from the engine itself, so the
numbers below are tropical and the comparison is exact.

Tolerances: Sun 0.5 degrees, Moon 1.0 degrees, Mercury to
Saturn 2.0 degrees, ascendant 1.0 degree, sunrise and
sunset 5 minutes, moonrise and moonset 15 minutes. The
tolerances are the engine own error budget from the
Schlyter elements, not a loosening to make tests pass.

## Boundary cases without an external reference

These are defined by the engine own rules and checked as
exact values, so they still fail loudly if the rule
breaks. No external number is invented for them.

Ayanamsa differences, J2000: Lahiri 23.853 degrees,
Krishnamurti 23.753, Raman 22.420. The test checks the
engine offsets: Raman is Lahiri minus 1 degree 26
minutes within 0.05 degrees, Krishnamurti is Lahiri
minus 6 arcminutes within 0.02 degrees. Published Raman
values range 22.38 to 22.43 across sources, so the offset
form is documented as an approximation good to about 3
arcminutes.
Node modes, canonical birth: true node minus mean node
is plus 0.70 degrees tropical by the Skyfield crossing,
and the engine true node must sit within 0.5 degrees of
the crossing value 160.61.
Divisional boundaries: a planet at 29.99 degrees in a
sign and the same planet at 0.01 degrees in the next
sign must land in adjacent Navamsha parts, and a planet
exactly on a 3 degree 20 minute Navamsha boundary must
take the later part. Checked in test/divisional_test.dart
with hand computed arithmetic in the comments.
Tithi and nakshatra boundaries: the new moon and full
moon cases above, plus the Amavasya fix already in
test/astro_test.dart.
Retrograde transitions: Jupiter motion changes sign
between 1 November 2025 (direct) and 1 December 2025
(retrograde), Saturn between 1 July 2025 (direct) and 1
August 2025 (retrograde). The test checks the sign of
the motion on both sides of each station, not the exact
station date, because the Schlyter elements put the
station within about a day of the JPL date.

## How to regenerate

Install Skyfield in a venv, download DE421 with curl
because the sandbox proxy breaks Skyfield own download,
then run the generator from the repo root. The ephemeris
file and the venv live outside the repo and are not
committed. Only reference_cases.json is committed, so CI
never needs the network or Skyfield.
